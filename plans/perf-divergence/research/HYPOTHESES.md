# Divergence hypotheses (HYPOTHESES — not findings)

Every entry is a **hypothesis** generated from planning-time reading of ORT v1.30.0 source (`research/rounds/round-1-A.md`, agent A) and spikes SP-5/SP-7. None is claimed to be true. They exist so the investigation ladder (D-106) exposes and measures the right things; **no decision, test or step depends on any of them being true** (Rule 8). The classifier is `metrics.classify_outcome`, not this list.

| ID | Hypothesis | Basis (labelled) | Where the ladder tests it |
|---|---|---|---|
| H-1 | InstanceNormalization computes mean/variance with Eigen reductions whose fp32 summation order depends on the build's SIMD packet width; native x64 and WASM builds therefore round differently, and a channel with tiny variance relative to its mean amplifies the difference. | A-1 verified in source (two-pass, epsilon inside sqrt); A-2 *inferred* (WASM Eigen packet type not verified). 74 InstanceNorm nodes; SP-7 shows the first InstanceNorm outputs already differ 8.9e-5, growing to 3.5e-3 two ops later. | D3 (all InstanceNorm outputs in encoder blocks 0–1), D4 (op-level vs float64 oracle). |
| H-2 | LayerNormalization takes different code paths: native x64 with AVX2+FMA3 uses an MLAS kernel (double-precision mean, centered two-pass variance, multiply-by-reciprocal), while ORT Web WASM has no MLAS LayerNorm kernel and always uses the scalar Welford fallback (divide by std_dev). On poorly conditioned rows the two differ, and one of them may be materially less accurate. | A-3, A-4, A-5 (v1.30.0 source, verified); PR #31973's own accuracy claim (A-11) is `single-source` and its release membership was not verified beyond the tag source. 26 LayerNorm nodes. | D3 (all 26 outputs are milestones), D4 (`judge_op` on LayerNorm nodes; oracle verified for LayerNormalization, C-113). |
| H-3 | Subnormal (denormal) float32 values arise in quiet stems on this degenerate input; native x86 handles them per MXCSR (ORT sets FTZ/DAZ **off** by default on the first session's main thread and pool threads), WASM never flushes and cannot honour `session.set_denormal_as_zero` — so a flush-to-zero difference could exist between the two in some configuration. By default both preserve subnormals, so this needs an additional trigger (e.g., host-process MXCSR state). | A-7, A-8, A-9, A-10 (source; A-10 *inference*). | D2 (native with `set_denormal_as_zero=1`), D3 (subnormal-fraction column). |
| H-4 | The network is ill-conditioned on exactly periodic, exactly mono input: any rounding-level disagreement between two *correct* runtimes is amplified into a large output difference (no op is defective). SP-3 found native itself insensitive to ±1e-5 input noise (≤ 1.4 %), which argues against *native* being ill-conditioned but does not rule out sensitivity to *systematic* (non-random) differences. | SP-3 (repo record); regenerated-chord non-reproduction (C-103) shows input-specific behaviour. | D1 (noise σ sweep breaking exact mono), D4 (all-`agree` ⇒ `AMPLIFICATION`), perturbation table. |
| H-5 | Conv / MatMul accumulation order (native AVX2/AVX-512 FMA kernels vs WASM SIMD128 without FMA) or the `Erf` polynomial differ enough to matter. | General knowledge of kernel differences; nothing model-specific verified. | D4 for the top-jump nodes. |
| H-6 | The WebGPU EP agrees with native (or with WASM) on the target chunk, indicating which side is the outlier. | Reasoning only (A-13/A-14 show WebGPU has had its own op bugs, so agreement is weak evidence either way). | D2 matrix (evidence only). |

Not hypothesised: ORT-version or build-flavour effects (SP-3 already found identical output for 1.22 vs 1.30 and JSEP vs plain), thread count (SP-3: identical 1 vs 4 threads), fp16 weights (SP-3: same for fp32), decoder differences (SP-3: ≤ 2.1e-6/sample).
